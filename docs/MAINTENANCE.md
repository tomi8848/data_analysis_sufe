# 维护说明

## 包的范围

`PACKAGE.json` 的版本指发布套件版本，不代表课件版本、模型版本或认证结果。初始发布套件版本为 `1.0.0`。

Skill 主流程与三份参考资料是既有版本的完整导出。此次补充仓库首页、安装与网页上传说明、案例及自动导入配置，未改变六项原则和七步分析流程。

## 更新分析规则

在使用 Skill 的平台上维护主流程和参考资料，再将验证后的内容导出到 `skills/analyze-data-with-evidence/`。仓库目录应保持同一套内容，不只更新单个 `SKILL.md` 而遗漏参考文件。

先用实例检查行为，再发布新版。至少检查：加权指标与业务意义、缺少数据时的诚实回答、预测时可用信息、因果与相关的区别。不要把一次例子通过说成对所有任务均可靠。

## 更新网页上传包

1. 更新需发布的 README、docs、examples 和技能文件。
2. 更新 `PACKAGE.json` 中的版本信息。
3. 选中这些顶层文件和目录，压缩为 `skill-repository.zip`。ZIP 内第一层应直接是 README.md、PACKAGE.json、docs、examples、skills，不增加仓库名称外层。
4. 保持初始文件集合与路径。若增删文件，在网页上单独更新工作流的 `ALLOWED` 列表后再导入。
5. 上传到仓库根目录。工作流会完整检查，再提交展开结果。

导入属于覆盖式更新，不负责删除旧文件；不再需要的文件由维护者单独处理。工作流自身始终单独维护，禁止通过上传 ZIP 替换执行逻辑。

## 本地核验与在线运行

本套件交付前检查了 ZIP 路径、链接、必需文件、导入幂等性与异常包拒绝，并在临时本地仓库模拟了提交行为。这不等于已经在你的 GitHub 账号中运行；GitHub Actions 的实际结果还取决于仓库权限、组织策略与分支保护。
