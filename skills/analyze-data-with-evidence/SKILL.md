# 问题驱动的数据分析

将问题、证据、结论和行动连接起来。以用户要求的语言沟通；没有明确语言偏好时用中文。遵守任务范围，用能回答问题的最小充分流程。只做方案时给方案，要求实际分析时执行到有可核对的结果。

## 读取参考资料

- 首次应用本 Skill 时读 [课件原则与来源](references/course-principles.md)，理解三份课件的关系和已明确的推断边界。无需重新索取原课件。
- 获取/清洗数据、比较指标、统计建模或制作图表时，读 [执行检查](references/execution-checks.md) 的相关小节。
- 需要分析计划、报告、行动建议或知识条目时，按需取用 [工作模板](references/work-templates.md)，不要为了套模板扩张任务。

## 贯穿全程的六项原则

1. **可复现**：保留原始输入、来源、版本、处理步骤、参数和环境。代码必须实际执行才可称“已运行”，核心数字必须可复算。
2. **数据诚实**：区分已知事实、假设、模拟与未知；报告关键反例、排除规则、尝试、局限和不确定性。不得为达到显著、提高模型分数或完善故事而选择性处理数据。
3. **问题导向**：先确定要回答什么及服务何种判断，再决定方法、数据需求和图表。允许探索提出新问题，但标明探索与事先计划的区别。
4. **受众适配**：按读者需要调整顺序、术语和细节，保持事实与关键限制一致。让每张交付图回答明确问题，保持精准克制。
5. **从简单开始**：先检查趋势、分组和简单基线。复杂方法须证明验证表现或决策价值的增益，并考虑解释与使用成本。
6. **可行动**：连接目标、约束、可选行动和评估方法。证据不足时把补数、试点或进一步验证作为下一步，不编造收益或强行下处方。

## 七步工作流

### 1. 定义问题与证据要求

先阅读用户已有说明和可用数据概况。用一句话确定对象、指标、时间、参照与待支持的决策或研究判断。明确一行粒度、目标总体、指标分子分母、单位、观察窗口、成功标准和受众。

需求模糊时先做能推进工作的来源/字段检查。只有缺失信息会实质改变分析方向时，集中问最少的关键问题；其他部分写明合理假设后继续。没有数据时交付可执行的分析方案、数据需求和验证设计，不虚构结果，也不声称已完成实证分析。

选择本次需要的分析类型，不要求逐层做全：

| 类型 | 回答 | 证据边界 |
| --- | --- | --- |
| 描述 | 发生了什么 | 指标、分布、趋势只能支持对应范围内的描述 |
| 诊断 | 有哪些解释 | 分组与分解定位结构或候选机制，关联不自动证明原因 |
| 预测 | 未来/未见结果可能怎样 | 需要可用特征、合理验证与适配的不确定性说明 |
| 规范 | 应选择什么行动 | 需要目标、约束、成本、效果依据和方案评估 |

按“问题 → 假设 → 方法 → 数据需求 → 图表”规划，遇到不足及时回退。需要解释时建立假设—证据表，同时写出反例；纯描述任务不强行发明原因。

### 2. 获取并理解数据

核对来源、版本、样本进入机制、时间覆盖、粒度、字段语义与可用范围，记录缺了谁、为何缺、可能怎样影响判断。

文件成功打开、API 返回成功或 SQL 能执行，都不等于数据正确完整。选择适配的解析方式并核对关键样例。必要的获取与分页检查见执行参考。仅使用实际可用且获准的访问方式，不把方法模板说成已经查询到的事实。

### 3. 清洗并保留处理依据

检查缺失、重复、类型、日期、单位、异常值及键关系。逐项记录处理规则、业务理由、影响数量和必要的敏感性比较。

区分缺失与零，保留编号语义。展开列表或多表连接时防止粒度变化造成重复计量。保留原始数据，输出另存；回读关键交付数据并核对结构和数字。

### 4. 探索分布、趋势与结构

从样本覆盖、基本分布、异常时间点和主要分组开始。先排除口径、埋点、更新延迟和观察窗口不足等问题，再解释业务变化。

复算总体与分组的分子、分母和权重，同时检查规模与平均水平。出现方向反转时说明目标总体和分组依据，不能断言“分组必然更正确”。检查选择/幸存者偏差、混淆、反向因果和小样本影响。

记录探索中新出现的假设。把能复算的结构变化、尚待验证的机制与已识别因果效应分开表达。

### 5. 选择方法并检验可靠性

按任务选择最小充分方法与基线，不默认每次都做回归、机器学习、显著性检验或四类分析。

依据数据结构检查统计假设和分析单位。需要推断时报告效应大小、区间与实际意义，处理相关性、配对/聚类或多重比较等实际问题。不能把不显著说成“没有影响”。

预测先明确预测时点及可获得的特征，再划分训练与验证；按时间/群体结构防止泄漏。用相同口径比较基线和候选方法。未来观测的预测区间与参数置信区间分开，不能估计的区间不编造。

因果结论须交代干预、对照、识别设计和假设；只有相关性或前后变化时保留候选解释。规范性建议须补全目标、约束、成本和评估条件。

### 6. 解释、可视化与沟通

先给对主问题的直接回答，再给支撑论点和可核查证据，最后说明限制与下一步。需要叙事时用 SCQA；用金字塔组织论证；用 MECE 检查分类是否重复或遗漏，不把它解释成统计独立。

使标题力度与证据一致：可写“客单价下降与新客占比提高有关”，未识别因果时不可写“促销导致下降”。每张图服务一个问题，交代单位、时间、分母/样本及必要来源；检查轴范围、面积、颜色、时间窗和基数，避免视觉夸大。

对齐正文、图表和摘要数字。区分百分点与相对百分比，精度匹配数据质量。按任务大小提供简明答复或完整报告，不强制固定图数、论点数或字数。

### 7. 给出行动、反馈与复用方式

给出与证据匹配的下一步，写明对象、目标、约束、执行角色、观察窗口、评估指标和成功/停止条件。条件未知时标为建议或待确定，不冒充已批准方案。用户只要事实分析时，可简述意义，无需硬添商业行动。

需要反馈时说明哪些新数据会改变判断，何时应重算或重新验证。提出部署方案不代表获得执行外部操作的授权。

对值得复用的结果，按授权范围保存问题、场景、适用代码、核对样例、注意事项、来源及版本。区分可复用方法和当次发现。未经验证的 AI 输出不能标为已验证知识，不自动向第三方写入或建立定时任务。

## 最后交付检查

按执行参考的六原则核对本次实际需要的项目。重点复查核心数字、分子分母、输入与输出一致性、验证是否独立、标题是否过度推断、关键未知是否标明。

交付应回答：**分析了什么，证据是什么，结论到哪一步，接下来做什么，如何复算。** 未执行的步骤如实标注，不把拟议检查列为已完成。用户要求文件时遵循相应文件技能的生成、检查与保存流程；日常问答无需强行产出文件。
