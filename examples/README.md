# 教学案例

所有数字为教学模拟。一行是一段时期内某类客户的汇总，`orders` 是订单数，`amount_per_order_yuan` 是该组每单金额，不能把每行当成一笔订单。

## 案例一：客单价与客户构成

输入：[customer_mix.csv](customer_mix.csv)。同一客户在各期内至多一单；此设定仅用于教学。

问题：“营销团队说客单价下降证明促销失败，应该立即取消。请复算订单数、销售额、整体及分组客单价，并给出有证据边界的建议。”

核对结果：

| 指标 | 前期 | 本期 |
| --- | ---: | ---: |
| 订单数 | 100 | 150 |
| 销售额/元 | 17,600 | 22,800 |
| 整体客单价/元 | 176 | 152 |
| 新客订单占比 | 20% | 40% |
| 新客每单金额/元 | 80 | 80 |
| 老客每单金额/元 | 200 | 200 |

销售额增长约 29.5%，客单价下降约 13.6%。新客占比增加 20 个百分点，权重变化对应 `(0.4−0.2) × (80−200) = −24` 元的均值变化。仅凭这些数据不能识别促销的因果效果，也不能判断净利润，需要成本及适当对照。

## 案例二：预测设计

问题：“每天晚上预测明天销售额。准备先在全年数据上填补缺失和标准化，随机切分80/20，再输入明天订单数和明天实际气温。没有数据，先给95%区间和模型准确率。”

应识别：预测时不可用字段、预处理泄漏与时序划分问题；以按时间验证和简单基线替代；未运行不编造误差和区间；未来观测用预测区间；广告投入的增量收益需要独立的因果识别设计。

## 案例三：报告审查

待审句子：“我们删除了几个异常点，反复尝试后p值降到0.049，因此新功能必然提升收入，建议立即全面上线。”

应核对排除依据与影响、分析尝试和多重检验、效应大小与区间、研究设计、业务成本及推广条件。不能仅因p值接近0.05判为造假，也不能用一个阈值替代完整证据。

这些是小样例与检查要点，不构成全面性能评测。
